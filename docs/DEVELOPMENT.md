# 麻将计分器开发文档

## 项目概览

这是一个纯前端微信小程序项目，用于记录麻将对局中的分数变化。当前版本不依赖后端服务，所有计分状态保存在微信小程序本地缓存中。

当前已实现能力：

- 上半部分为四方位计分布局：上北、下南、左西、右东。
- “我”固定在下南位，可通过微信小程序 `chooseAvatar` 能力选择头像。
- 北、西、东三个方位支持输入本局分数变动。
- 点击“提交”后，将本局输入累计到各方位总分。
- 上半部分中央展示“我的分数”，按其他三家累计分的反向值计算。
- 下半部分展示计分历史，每局一行，格式为 `第X局：北+1  西-2  东+1`。
- 支持重置全部分数和历史记录，重置前会弹窗确认。

纯前端限制：

- 无法跨设备同步数据。
- 无法多人实时共享同一计分房间。
- 无法静默读取微信头像，必须由用户点击头像并授权选择。
- 卸载小程序或清理微信缓存后，本地数据可能丢失。

## 运行方式

1. 打开微信开发者工具。
2. 选择“导入项目”。
3. 项目目录选择当前仓库根目录。
4. `AppID` 可先使用测试号或游客模式；当前 `project.config.json` 中为 `touristappid`。
5. 编译后进入首页即可使用。

如果后续要发布正式版本，需要将 `project.config.json` 中的 `appid` 替换为真实小程序 AppID。

## 核心数据模型

核心状态定义在 `pages/index/index.js` 的 `Page.data` 中：

```js
{
  players: [],
  round: 1,
  history: [],
  totalScore: 0,
  myScore: 0
}
```

### players

`players` 是四个方位玩家列表，初始值来自 `initialPlayers`：

```js
{
  key: 'north',
  direction: '北',
  label: '上北',
  score: 0,
  input: '',
  avatar: '',
  isMe: false
}
```

字段说明：

- `key`：内部唯一标识，用于样式定位和输入事件匹配。
- `direction`：历史记录中展示的方位名称。
- `label`：页面上展示的方位标签。
- `score`：该方位累计分数。
- `input`：本局待提交的输入值。
- `avatar`：头像地址，目前只用于“我”的头像。
- `isMe`：是否为当前用户。“我”固定为南位。

当前方位约定：

- `north`：上北
- `south`：下南，也就是“我”
- `west`：左西
- `east`：右东

### round

`round` 表示下一次提交对应的局数，初始值为 `1`。

每次有效提交后：

- 本次历史记录使用当前 `round`。
- 提交完成后 `round + 1`。

### history

`history` 是计分历史列表，最新记录排在最前面。每次提交只生成一条历史记录。

单条结构：

```js
{
  id: '1-时间戳',
  text: '第1局：北+1  西-2  东+1'
}
```

### totalScore

`totalScore` 是四个方位当前累计分数之和，目前仅作为内部保留字段，不直接展示。

### myScore

`myScore` 是页面中央展示的“我的分数”。由于“我”固定在南位且没有分数输入框，当前按其他三家累计分的反向值计算：

```js
myScore = 0 - north.score - west.score - east.score
```

例如北、西、东分别累计 `+1`、`+1`、`+1` 时，我的分数为 `-3`。

## 本地缓存

缓存 key：

```js
const STORAGE_KEY = 'mahjong-scoring-state-v2'
```

相关方法：

- `restoreState()`：页面加载时从本地缓存恢复数据。
- `persistState(nextState)`：头像选择或提交计分后保存数据。
- `resetScores()`：确认重置后清空页面状态，并删除本地缓存。

缓存内容：

```js
{
  players,
  round,
  history,
  totalScore
}
```

## 页面交互流程

### 选择头像

位置：`pages/index/index.wxml`

“我”的头像按钮使用：

```xml
open-type="chooseAvatar"
bindchooseavatar="onChooseAvatar"
```

处理逻辑：

1. 用户点击下南位头像。
2. 微信弹出头像选择能力。
3. `onChooseAvatar` 获取 `avatarUrl`。
4. 更新南位玩家的 `avatar`。
5. 将状态写入本地缓存。

### 输入分数

北、西、东三个方位展示输入框。

输入框使用 `type="text"`，而不是 `type="number"`，原因是微信数字键盘对负数输入支持不稳定。当前通过 `Number(value)` 在提交时转换输入。

### 提交计分

入口方法：`submitScores()`

处理流程：

1. 遍历 `players`。
2. 将每个玩家的 `input` 转为数字。
3. 忽略空值、非法值和 `0`。
4. 对非零输入：
   - 累加到该玩家 `score`。
   - 收集为本局历史记录的一部分。
   - 清空输入框。
5. 如果没有任何有效输入，弹出 `请输入分数`。
6. 重新计算 `totalScore` 和 `myScore`。
7. 将本局所有变化合并为一条历史记录并插入列表顶部。
8. `round + 1`。
9. 保存到本地缓存。

### 重置

入口方法：`resetScores()`

处理流程：

1. 点击右下角半透明“重置”按钮。
2. 调用 `wx.showModal` 展示确认弹窗。
3. 用户确认后：
   - 玩家分数归零。
   - 局数回到 `1`。
   - 历史记录清空。
   - 全局累计归零。
   - 删除本地缓存。

## 样式布局说明

页面分为上下两块：

- `.score-panel`：上半部分计分布局。
- `.history-panel`：下半部分历史记录。

四个方位通过绝对定位实现：

- `.north`：顶部居中。
- `.south`：底部居中。
- `.west`：左侧居中。
- `.east`：右侧居中。

“我的分数”通过 `.center-score` 放置在麻将桌中心。

重置按钮 `.reset-button` 使用绝对定位放在历史面板右下角，并使用半透明红色背景。

## 迭代建议

可优先考虑的后续功能：

- 增加“撤销上一局”功能，降低误操作成本。
- 支持编辑或删除单条历史记录。
- 增加输入校验，例如要求每局四方总和为 `0`。
- 支持给北、西、东三家设置昵称和头像。
- 支持切换庄家，并在界面上标记庄位。
- 增加对局结束统计，例如最高分、最低分、每家净胜负。
- 增加导出记录能力，例如复制文本或生成图片。
- 引入云开发或后端服务，实现多设备同步和多人共享。

## 修改注意事项

- 如果调整方位，请同步修改 `initialPlayers`、样式类名和历史展示逻辑。
- 如果改动 `players` 数据结构，需要同时考虑本地缓存兼容性。
- 如果后续增加后端同步，建议先抽出独立的数据读写层，不要把接口请求直接散落在页面事件中。
- 如果增加复杂计分规则，建议把计分逻辑从 `index.js` 拆到独立模块，便于单元测试。
- 当前 `history.id` 使用局数、方位和时间戳拼接。若后续支持编辑、同步或跨端合并，建议改为更稳定的唯一 ID。

## 手动验收清单

每次修改后建议在微信开发者工具中验证：

- 首次打开页面时，四个方位显示正确。
- “我”固定在下南位。
- 点击“我”的头像可以选择微信头像。
- 北、西、东输入正数后，提交能正确累计。
- 北、西、东输入负数后，提交能正确扣分。
- 空输入或全部为 `0` 时，点击提交会提示 `请输入分数`。
- 提交后输入框会清空。
- 中央全局累计分会更新。
- 历史记录会按最新在前展示。
- 关闭并重新打开小程序后，本地数据能恢复。
- 点击重置后弹出确认框。
- 取消重置不会清空数据。
- 确认重置会清空分数、历史和缓存。
